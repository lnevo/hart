01The roster on the throttle

Tool
Claude
When
November 2026
Status
Public; in service

The job

A locomotive has to be known in the DecoderPro roster and in the command station, and there are two kinds of throttle in people’s hands. WiThrottle throttles on phones take their list from the JMRI roster. LCC throttles take theirs from the command station, a TCS CS-105, which speaks LCC. Both should list every locomotive by name with the function buttons labelled. Keeping the command station in step with the roster by hand does not last.

What AI did

DecoderPro can copy a roster entry into the command station only if the command station already has a train for that address, and there is no way to say “create it”. So the copy runs from inside JMRI instead: it reads the roster, asks the command station to create any train it is missing, and writes the name and function labels into each one. It refuses to apply anything when no CS-105 answers on the LCC bus. A small tool restarts the command station over LCC, and a helper builds a consist, with CSX 2121 leading and 2738 following in reverse, headlight linked.

What came out

Every roster locomotive on the CS-105 by name, with the right buttons, so the LCC throttles list the same locomotives as the WiThrottle ones. The script is now its own public project so other modelers can use it.

Some things only showed up by trying. The command station keeps a train through a restart only once the train has a name; four came back blank the first time. The roster IDs became road and number, such as CSX 2121, because that is what the WiThrottle phone throttles show, and the CS-105 train names were matched to them. And the script that copies the roster to the Windows computer reported success for a while and delivered nothing, because the files were packed with absolute paths. Now the copy checks every file afterwards and fails loudly if any is missing.

Verdict
  • Worked well: a script inside JMRI that creates the missing command-station trains and copies the roster into them.
  • Lesson: a script that says it worked is not proof. Check the far end.

See it: jmri-cs105-roster-sync on GitHub

02Roster photos

Tool
Claude
When
November 2026
Status
Thirteen locomotives so far

The job

The roster, the cards and the website all want a picture of each locomotive, and they should look like a set.

What AI did

A small tool cleans each photo the same way: level, a loose crop with room round the locomotive and track, colour and exposure left alone, a smooth grey backdrop and a soft shadow under the track. The two halves of a consist face opposite ways.

What came out

Thirteen locomotives with a photo in the roster, installed on every computer; the newest are on the site too.

Verdict
  • Worked well: a consistent look once the style was fixed.
  • Needed me: the style. The car-photo tool, tried first, cropped too tight, tilted a level photo and blew out the exposure, and a pure white backdrop was rejected. I approve the sheet before anything is recorded.

03Speed matching

Tool
Claude
When
November 2026
Status
2738 matched to 2121; first coupled run to come

The job

Two locomotives that run at different speeds cannot work together; one drags the other. I wanted CSX 2121 and 2738 to run as a pair.

What AI did

A program running inside JMRI set each locomotive to a throttle step, let it run laps of the whole loop and timed each lap from the block sensors, step after step, with no hands on the throttle. Both topped out at about the same speed, but 2738 ran at only 47 to 74 per cent of 2121’s speed through the lower steps. Its settings explained why: the speed table was switched off and it had no momentum.

I chose to match 2738 to 2121, momentum included. It was programmed on the programming track with a calculated speed table, and every value read back correctly. Measured again at steps 24, 48 and 126 it ran within 1.2 per cent of 2121, and about 5 per cent fast at step 12. At step 96 the two stopped within a tenth of a second of each other and started within three tenths.

What came out

A matched pair, ready to be tried coupled, and a method to repeat for the other fifteen locomotives.

Verdict
  • Worked well: hours of unattended, repeatable measuring, and a speed table worked out from the numbers rather than by feel.
  • Be honest about: the speeds are relative. The block lengths used to turn lap times into real speeds came from the track plan, and the timings show several are wrong, so scale miles an hour cannot be trusted yet. The comparison between the two is not affected, but they were timed running in opposite directions, so a direction effect is mixed in. Measuring the real blocks comes next.

See it: Speed matching and the measure table (the Short Track Rail Road club's procedure, PDF, 37 pp, which HART is adapting for HO)
