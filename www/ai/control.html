This topic covers four projects: turning the track plan into JMRI panels, building the dispatcher desks, settling the signals, and keeping JMRI's setup in one tables file. I tried several signal systems before settling on JMRI's own Signal Mast Logic. CATS is used for CTC, and PanelPro for everyday running.

01Track plan to panels

Tool
Cursor
When
January to June 2026
Status
Done; first production panel May 2026

The job

The track plan was drawn in AnyRail. JMRI needs its own Layout Editor panel, a drawing that knows where every track, turnout and block is. Drawing that by hand would mean doing the plan twice.

What AI did

It wrote a pipeline that turns AnyRail exports into Layout Editor panels. Each generation did the job better than the one before.

What came out

The panel JMRI runs on. Today the panel is kept as a physical picture of the layout and is changed in place.

Verdict
  • Worked well: getting from a drawing to a working panel without retracing it.
  • Lesson: a generator is great for the first version. After that, the panel itself became the thing to keep right.

The job

A dispatcher needs a CTC board: levers or buttons to line routes and clear signals, and lights that show where the trains are.

What AI did

The CATS desk was drawn in its Designer as the main dispatcher's desk, and a stock JMRI USS CTC machine was built beside it as an alternate. Both were redrawn step by step from the first pilot to the finished board. The JMRI Dispatcher System was set up to run trains automatically.

What came out

Two desks, never run at the same time, with guides for the person in the chair.

Verdict
  • Worked well: wiring hundreds of panel items to the right JMRI names without typos.
  • Needed me: how a desk should feel to use. That only came from sitting at it.

When

Stock JMRI install

The job

The signals in the aisle have to show what the dispatcher has lined and what the track ahead allows, and keep doing something sensible when nobody is dispatching.

What AI did

Several signal systems were tried through September. Grok helped with part of turning the route logic into JMRI's own Signal Mast Logic, which ended up owning the aspects. Claude then took the custom pieces back out. The signals now run on Signal Mast Logic in a stock JMRI install, plus the scripts and files listed on the JMRI additions page.

What came out

Signals that run on a stock JMRI install, and a list of the scripts and files added to it.

Verdict
  • Worked well: trying several designs quickly.
  • Lesson: AI builds workarounds unless told otherwise. Fixes were made in the tables data, not in JMRI's code.

04One tables file

Tool
Claude
When
October 2026 on
Status
In service

The job

JMRI keeps every block, switch, signal and route in tables. With three computers running JMRI, there have to be not three slightly different copies but one.

What AI did

It brought everything into one tables file kept in the repository, installed the same way on every computer. Scripts check it before every change, and a change saved in JMRI is pulled back into the repository before anything else touches it. A browser for its tables was built for this website from the same file.

What came out

47 signal masts, 105 sections and 777 transits (the routes the automatic dispatcher can run), all in one place, and the same on every computer.

Verdict
  • Worked well: careful, repeatable edits to a large XML file, with a check before each one.
  • Rule that came with it: never edit the file while JMRI has it open, because JMRI will write over the change.
