# HART Operator Portal

Crew-facing Neville Island site (not an engineering desk).

## Share it

Public URL: **https://www.hartrailroad.com/**, the only public copy. The GitHub Pages site (lnevo.github.io/hart) and its Actions workflow were removed 2026-10-17. Redeploy:

```bash
./www/scripts/deploy_hartrailroad.sh            # --force: deploy despite a count drop
```

Deploys from your **local working tree** (any branch, work in progress included). Run it after every portal change; it is separate from `sync_hart_package.sh` (layout hosts).

**Build rules** (`scripts/prepare_github_pages.py [DEST] [--site-url URL] [--full]`; the name predates the move off Pages). The photo stages (logos, photos, card thumbs, WebP) are reused from the last full run when their inputs are unchanged, stamped under `.cache/hart/web-jpeg/photo-group/`; any doubt prints `photo stages: full run (reason)`, and `--full` always rebuilds them:

- Only **git-tracked** files are published, with their working-tree content. A new page or image stays off the site until it is `git add`ed (committing is not needed).
- To keep a tracked file off the site, add it to `SKIP_FILES` (one file), `SKIP_DIRS` (a folder), or `SKIP_GLOBS` (a pattern) at the top of the script. `scripts/`, `review/`, `tools/`, `reference/`, `README.md`, `docs/*.md`, and invitation drafts are already skipped.
- **WebP:** after the pages are copied, a static `<img>` whose JPEG is over 200 KB gets a `.webp` beside it and is wrapped in `<picture>` with the JPEG as fallback (the build prints the bytes saved; images a script draws and WebP files under 15% smaller are skipped). Keep the JPEG original in the tree. The home hero is the hand-made 1200 px `birdseye-neville-island-1200.jpg` and `.webp`.
- **Provenance:** every published page must be classified in `scripts/provenance.json` as `prototype` (real history), `fiction` (HART's invented operation), `hobby` (documentation of the model) or `mixed` (name the sections), by exact path or folder; the build fails on an unclassified page. The build writes the class into each page's head as schema.org JSON-LD (fiction as a `CreativeWork` with `genre: Fiction`, history as an `Article` whose `citation` comes from the page's own `Sources` list), and writes `llms.txt`, `robots.txt` and `sitemap.xml` at the root. Redirect stubs and noindex pages are left out. Each page with content of its own also gets `<link rel="canonical">` to its `www` URL (folder pages as the folder), so Search Console counts the bare domain and `/index.html` as copies; stubs, noindex pages and `404.html` get none. The P&OV is real history; only HART and its P&CV Division are invented.
- Elements marked `data-local-only` are **removed** from the built HTML (and also hidden by `js/nav.js` when `site.public`), so use it for localhost and workspace links. `site.json` `tools` (localhost service URLs) is dropped, and any data field still pointing into `../external/` is removed.
- **Leak check:** the build fails, listing file and line, if the output still contains `localhost`, `127.0.0.1`, `/Users/`, or `external` (or `../external/` in data). Fix the source text or skip the file.
- Gallery and rolling-stock items get a ~640 px grid thumbnail (`assets/gallery/thumbs/`, `assets/fleet/thumbs/`, field `thumb`) and the full image's `width`/`height` when Pillow is installed.
- The 404 page is `404.html`, a train order annulling the missing page, with a rotating "cause of delay" line (the list is in the page's script). Its styles are in the page, and it uses site-root links (`/css/ops.css`, `/`) because it is served for any missing path, so locally it only draws properly from a built tree (below). The host serves it for missing paths (see the server notes below). `SITE_URL` (share tags) can be overridden with `--site-url` or `HART_SITE_URL`.

**Deploy safety** (`deploy_hartrailroad.sh`):

- Stops when this checkout lacks commits on `origin/main`, or when `origin/main` cannot be fetched, since `rsync --delete` would take the missing pages off the site; `--allow-behind` overrides. Warns, without stopping, when deploying from a branch other than `main` ([ADR-040](../wiki/decisions/ADR-040-site-deploys-recorded-current-one-at-a-time.md)).
- One deploy at a time: a lock (`hart-site-deploy.lock` in the shared git dir) stops a second deploy from any worktree while the first runs, and is taken over when its PID is gone.
- After the copy, the manifest records the commit, branch, dirty flag, worktree and time; `make orient` shows them on its `website:` line, and `deploy_hartrailroad.sh --status` prints the record.
- Refuses to run when `ops/hart-ops/operator_logos` is missing (logos would drop out, and `rsync --delete` would remove them live). Warns, without stopping, when the portal has uncommitted changes.
- Runs `scripts/check_portal_build.py --dist` on the build: every internal `href`/`src` in the HTML and every link/asset field in `data/*.json` must resolve to a built file. Run it alone (`python3 www/scripts/check_portal_build.py`) to build into a temp folder and check.
- Prints a manifest (file count, HTML pages, share cards, archive items, industry logos, gallery and fleet items) and compares it with the last deploy's, kept in the gitignored `.deploy-manifest.json` at the main checkout's root (found through the shared git dir, so a worktree deploy uses the same record). A count down more than 10%, or no manifest at all, stops the deploy unless `--force` is passed. The manifest is saved only after a successful rsync.
- Stops before building when a public photo's original is missing (`--require-mirrors`). The layout, rolling-stock and archive originals live in the gitignored `media/` and `ops/car-cards/`, which only the main checkout has. To deploy from a worktree, symlink both from the main checkout first; `--force` does not skip this check.

Server notes. Logins, key files, host names, addresses, firewall rules and server paths are kept out of this public repo, in the owner's private notes (`private/web-server/` in the main checkout, gitignored). What the repo needs to know:

- Deploys use an rsync-only ssh alias, `hart-deploy` (set up in `~/.ssh/config`), that cannot open a shell. It needs a real rsync on the Mac (`brew install rsync`; macOS `/usr/bin/rsync` is openrsync, which the server's rrsync rejects). `HART_WEB_HOST` with `HART_WEB_DOCROOT` falls back to a normal login.
- The server's nginx template for the site adds `Cache-Control: no-cache`, the HTTP→HTTPS redirect (ACME challenges exempt) and the security headers (HSTS, nosniff, Referrer-Policy, `frame-ancestors 'self'`, a report-only CSP). nginx drops outer `add_header`s inside a location that sets its own, so the headers are repeated per location. **Do not add a `types {}` block**: it replaces nginx's MIME map and breaks CSS/JS site-wide.
- Missing pages get the site's own `404.html` (a tracked page, deployed with the site) for 403 and 404 (since 2026-11-09); a 403, such as a folder with no index page, answers with status 404 (since 2026-11-26). nginx ignores `.htaccess`. The template carries the change, so a panel rebuild keeps it.
- nginx `open_file_cache_valid 60s`: a deploy can take up to a minute to appear. Verify with `until curl -s http://www.hartrailroad.com/… | grep -q "<new text>"; do sleep 3; done`.
- Industry logos come from `ops/hart-ops/operator_logos/`; the deploy refuses to run without that folder, because `--delete` would remove the logos live.
- Rolling stock photos (car sides, aisle set) come from the gitignored `media` and `external/sts-docker-data` mirrors; the site build (`prepare_github_pages.py`, its photo stages in `portal_photos.py`) resizes them into `assets/fleet/` (needs Pillow). Without the mirrors (or Pillow) those albums drop out and only Power shows.
- Historical archive images (`data/archive.json`) also live in those mirrors (`f-root/`, plus new finds in `desktop-data/archive-incoming/`); the site build (`portal_photos.py`) resizes them into `assets/archive/` with grid thumbnails in `assets/archive/thumbs/`, and drops items whose original is missing.
- Resized photos are kept in `<main checkout>/.cache/hart/web-jpeg` (gitignored, shared by every worktree; `HART_CACHE_DIR` moves the base) between builds, keyed on the original's bytes, the size and the JPEG settings, so a build re-encodes only new or changed photos (about 2 s instead of 27 s). `HART_WEB_JPEG_CACHE=` (empty) builds without it; photos unused for 60 days are removed.
- Favicon and share previews: the site build (`prepare_github_pages.py`, its head stage in `portal_head.py`) adds the favicon links and Open Graph tags (title from each page's `<title>`, image `assets/icons/share-card.jpg`) to every HTML page at build time, so source pages don't carry them. Icons come from `assets/media/hart-logo.png`. After changing them, re-scrape in Facebook's Sharing Debugger (developers.facebook.com/tools/debug).
- **Share thumbnails:** a page listed in `scripts/share-cards.json` gets its own preview picture (`assets/share/<name>.jpg`, 1200 x 630) in place of the site card. Every page in Operations, Behind the Scenes and The Diverging Route should have one (`"shared": true` lets pages the owner names use one picture, as the station maps, the paperwork index, yardmaster sequence, Guides hub and a few documents do; a page the owner wants left on the site card goes in `NO_CARD_PAGES` in `share_cards.py`), the station maps keep the site card), showing the page's own subject, not its section, and no picture is used twice. Make one with `python3 www/scripts/share_cards.py make SOURCE assets/share/NAME.jpg --focus X,Y`, add the entry (`image`, `alt`, `from` = where the picture came from), and `git add` the image. Cards that are drawn or composed (route map, editor view, panel slices, page snapshots and the like) are rebuilt with `python3 www/scripts/make_share_cards.py [NAME]` (`--list` shows them; captured source pictures are in `scripts/share-card-sources/`), so add a recipe for any new one: a function in `scripts/share_card_recipes/`, listed in `CARDS` in `make_share_cards.py`. Hub cards can show these pictures too: mark a `card-grid` with `data-card-thumbs` and the build puts a small copy (`assets/share/thumbs/`, made at build time, not tracked) of the linked page's picture on top of each card, muted until pointed at. A card that links to a page section (`build/index.html#staging`) or off the site (GitHub) can have its own picture in the `links` table of `share-cards.json` (same fields; centre crops with `share_cards.py make` are fine, composed ones get a recipe); these are used only on hub cards. A card with no picture, or one that would repeat a picture in the grid (shared cards), gets a plain band, which reads as a missing picture, so mark only grids where every card has one. Marked: The Diverging Route, Behind the Scenes, Guides, History and Operations hubs. A `links` entry for a whole page overrides that page's share picture on hub cards only, as the Operations paperwork cards do with photos from the session-night album. `python3 www/scripts/share_cards.py check` (also run by `check_portal_build.py`) lists pages still on the site card as a suggestion and fails on a broken or repeated card.
- Pages fetch JSON with `cache: "no-cache"`; keep that on new fetches so browsers don't hold stale data.
- **HTTPS** via Let's Encrypt, renewed by the server's panel (reissued 2026-11-23). Plain HTTP redirects to HTTPS (since 2026-10-17). The bare domain `hartrailroad.com` redirects (301) to `https://www.hartrailroad.com`, the one host name the canonical links and sitemap use (since 2026-11-26).
- Live tools links to `localhost` services exist only on the local portal; the build strips them (`data-local-only`, `site.json` `tools`).

## Open it locally (required)

JSON pages (Briefing, About, Photos, Layout, spot sheets) need **HTTP**, not `file://`.

```bash
# from repo — includes the archive and gallery edit APIs; edits must come from a local page (JSON body, local Origin)
# Login LaunchAgent (survives Cursor quit; starts at login). Disabled since 2026-11-11:
# start the preview on demand for pre-deployment testing (ADR-020 amendment).
./www/scripts/install_portal_launchagent.sh
# Foreground only (dies when the terminal/Cursor session ends):
./www/scripts/serve_portal.sh [PORT]
# → http://127.0.0.1:8760/www/
```

Plain `python3 -m http.server` works for read-only pages but **cannot save** archive or gallery edits.

Some files the site publishes are built, not committed ([ADR-036](../wiki/decisions/ADR-036-generated-views-not-committed.md)): `library/pipeline-map.html`, `data/tables-browser.json`, `data/layout-index.json`, `data/layout-index-cats.json` and `data/wiring-inventory.json` (the list is `VIEWS` in `scripts/site_views.py`). The wiring viewer (`behind/wiring.html`, `js/wiring.js`) reads the last one, which `scripts/build_wiring_json.py` builds from the wiring model (`hartlib.wiring`, through `tools/wiring/write_inventory.py`); its `--check` builds it in memory and runs its checks. `serve_portal.py` builds them all into `www/` when it starts; one that cannot be built is removed, named on the terminal with `NOT SERVED`, and the page that reads it shows its load error. `make site-data` builds them without starting the server (a plain `http.server` serves only what is in `www/`). The site build writes its own copies and stops when one cannot be built.

## Writing

Page text states what the page covers and the facts, in plain words. An intro is a short summary of the page plus its key facts. Readers notice text that sounds written by AI, and the owner rejects it. Avoid these, with real examples the owner removed:

| Avoid | Rejected example | Instead |
|---|---|---|
| Speaking for the reader or the exam | "People mix the two up; the exam won't." · "The terms are often confused." | Delete the clause; the definition is enough. |
| Invented colour or reasons the source does not give | "That stops crews waiting forever on a train that was annulled or forgotten." · "which can take 30 days or more" (not in OPSIG's rules) | Only what a source or the railroad's records say. |
| Coaching asides | "Picture eastbound No 7…" · "Think of the motion" · "so learn these exactly" | "Example: eastbound No 7…" · state the rule. |
| Tidy morals and closing summaries | "the log is only as good as my notes" · "so a spare evening can go to the one that is closest" · "This guide explains the ideas; the cards and tests check them." | End on the last fact. |
| Balanced, hedged framing | "AI made it cheap to try an approach, which is good, and it also made it easy to build something clever…" · "The direction that won in the end was the plainest one." | Say what was tried and what is used now. |
| Metaphor and story openers | "It is the destination at the end of the main line…" · "I wanted one place that says…" · "This topic has the most trial and error in it." | Open with what the thing is. |
| Hedges | "would fit" · "would do it" | "is a candidate" · "not yet checked". |
| Stock phrases | "the key is", "here's why", "worth noting", "the rule also works the other way", "a good place to start", "X, not Y" for effect | Plain statement. |

When cutting filler, keep any fact or rule inside the sentence; rewrite it plainly rather than deleting it. A suggestion is not a fact: do not turn "would do it" into "counts" without a source. Never write a claim about a program's rules (NMRA, OPSIG) that its own pages do not make.

`python3 tools/audit/check_ai_speak.py` (run by `tools/check.sh` and CI) flags the known phrasings on the article pages (AI topics, library, behind, guides, AP, exam). It cannot catch everything above, so read new prose against this table too. The "Worked well / Needed me" labels on the AI topic pages are the series format; keep them, and keep what follows them factual.

## Site search

The magnifier in the header (or `/`) searches `search-index.json`, which `prepare_github_pages.py` writes into the build from the built pages and the public data files (pages, articles, glossary terms, industries, crew sheets, rolling stock, archive items, layout photos). It is never in the source tree, so a page served from `www/` shows no search button. `js/search.js` does the matching in the browser; nothing is sent anywhere.

- **Order:** exact title hits first ("2738", "NVL", "YM-01"), then groups: Pages & articles, Railroad, Photos & archive, with **Rolling stock always last** (owner's rule). Rolling stock leads only for a number, never for a road name.
- **Forgiving:** `&`/"and" and punctuation are folded ("ym01" finds YM-01), a typed word of five or more letters may have one typo (it can match a shorter word: "cokee" finds "coke"), and road names in the `SYNONYMS` table find each other. P&CV and P&OV are different names and never share a row.
- **Links:** items open on their page (`photos/#rolling-stock/<id>`, `#historical/<id>`, `#layout/<id>`, glossary and spot-sheet anchors). Every fleet and gallery item needs a unique `id`; `check_portal_build.py` fails the build otherwise, and checks every index link and thumbnail.
- **Thumbnails:** the build makes 80 px copies in `assets/search/` (needs Pillow).

## Layout Explorer data

The page (`layout/index.html`, `js/layout-explorer.js`) opens at Fit, with the frame in the board's own shape. Zoom with + and −, the slider, a trackpad pinch, Ctrl/⌘ + wheel or a double-click (Shift zooms out); each keeps the point under the pointer or the view centre in place. Drag pans. Switch and mast dots keep at least 12 px on screen however far out the map is zoomed. Once zoomed in, an overview in the corner shows the whole board with a box round the view; click or drag in it to move. The arithmetic is in `js/map-view.js`, tested by `scripts/tests/map_view_test.js` (node).

`data/layout-index.json` (from live repo data) and `data/layout-index-cats.json` (from `cats/panels/HART_CTC.xml`, joined to the layout index) are not committed ([ADR-036](../wiki/decisions/ADR-036-generated-views-not-committed.md)): the site build and the local preview build them (`scripts/site_views.py`). The two PNGs they sit on, `assets/layout/HART_le_schematic.png` and `assets/layout/HART_cats_digicon.png`, are committed, each with a stamp of what it is drawn from (`scripts/png_stamp.py`). After the layout or the desks change, run `python3 www/scripts/build_layout_index.py` and `python3 www/scripts/build_cats_layout_index.py` to redraw and restamp the PNGs, commit them, then deploy; their `--check` (in `tools/check.sh`) builds the JSON in memory, runs its checks and fails on a PNG drawn from other inputs.
