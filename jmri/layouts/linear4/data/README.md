# linear4 device mapping data

Regenerated by `jmri/scripts/build_linear4_device_mapping.py` from:

- **Live devices:** repo root `tables.xml`
- **Geometry:** `linear4.xml` / `anyrail/linear4.xml` (18 turnouts)
- **Blocks:** `output/linear4_blocked.xml` (47 blocks, BS occupancy sensors)

## Files

| File | Purpose |
|------|---------|
| `turnout_mapping.csv` | Each linear4 ident → live panel system name, MQTT user name, DCC address, feedback sensors |
| `sensor_mapping.csv` | Turnout feedback (from live) + block occupancy rows (`BS …` placeholders for future M2S wiring) |
| `dcc_label_placement.json` | Per-switch DCC label offsets; preset `split` (west above, main line below) |
| `layout_area_labels.json` | Neville Island, yard names, direction row positions |
| `layout_blocks.xlsx` | Block naming spreadsheet (from `build_blocks_excel.py`) |

## Regenerate

```bash
# CSVs only
python3 jmri/scripts/build_linear4_device_mapping.py

# CSVs + dev panel + production panel
python3 jmri/scripts/build_linear4_device_mapping.py \
  --write-panel --write-prod-panel --dcc-label-placement split
```

Production load: **`../output/linear4_prod.xml`**

## Turnout block comments

Turnout blocks in the panel use **MQTT switch user names** in the Blocks table `<comment>` field (e.g. `TOR14` → `MQTT Switch 3-8`), taken from the `live_mqtt_user` column in `turnout_mapping.csv`. Internal `BS TOL…` sensor comments stay as layout idents.

## Review / edits

1. Check rows with large `match_dx_px` in `turnout_mapping.csv`.
2. To change hardware assignment, edit **`CURATED_PANEL_SYSTEM`** in `build_linear4_device_mapping.py` (linear4 ident → `M2T*` or `IT*` for crossover legs), then rerun the script.
3. Fill `live_physical_system` / `live_physical_user` in `sensor_mapping.csv` when block sensors are wired to M2S* hardware.
