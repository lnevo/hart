- **Stock distributions:** JMRI 5.16 and CATS 3.2 run unpatched on all three hosts since 2026-10-31, under monitoring. If something breaks, compensate around them rather than changing them. JMRI Simple Server (port 2048) starts with each profile so CATS finds its operations server. The Pi profile's ignored old 2-9-6 `<startup>` block was removed on 2026-11-10 (backup `profile.xml.bak_old_startup_20261110`).
- **Network (2026-11-11):** the Pi (`RPi-JMRI`, 10.0.0.150) is on the house Wi-Fi directly; it no longer goes through the Windows mini PC's connection sharing (192.168.137.x is retired). Mosquitto runs on the Pi: the Pi profile uses `127.0.0.1`, while Windows, the Mac and the LCOS bridge use `10.0.0.150`. Windows (`MINIPC-E5H6X`) is `minipc-e5h6x.local` (10.0.0.28, SSH port 2222); that name is the Windows box, not the broker. Windows launchers no longer read the old `Dropbox\HART_sync` folder.
- **Throttle Wi-Fi (`RPi-JMRI` SSID):** served by a GL.iNet MT300 (OpenWrt, 10.0.0.62 on the house side, LAN 10.42.0.0/24), uplinked over Wi-Fi to the nearest house access point (pinned). An avahi reflector carries WiThrottle discovery across, and WiThrottle works. Its firewall lets clients reach the house only on JMRI web 12080 and WiThrottle 12090. MQTT is not needed from there. STS runs on the Pi (10.0.0.150:8980, ADR-020) and is to be opened there. The LCOS mimic runs inside JMRI on the Pi at `/web/mimic/` (port 12080, already open), with `mimic_relay.py` publishing its clicks. Do not share the Mac's internet over Ethernet into it: its DHCP switches off when it sees another DHCP server.
- **MQTT startup race:** Expect `ConcurrentModificationException` with `Can't subscribe` at startup: a JMRI race that drops the broker for a few seconds, then reconnects and resubscribes on its own (seen on the Mac 2026-10-31, on the Pi 2026-09-06). Retained messages alone trigger it, with no HART scripts running. Worry only if `Succeeded to reconnect` does not follow.
- **CATS load risk:** a turnout report during panel load can raise `NullPointerException ... requestLockClear` and kill the CATS event thread, freezing occupancy and turnout control. Do not move turnouts while CATS starts. If that error appears or occupancy stops updating, restart CATS. After CATS starts, use Appearance → Refresh Screen. Never use Refresh Layout: it can move points to a stale route.
